# AI Agent for Chrome Automation

Автономный AI-агент на Go для управления видимым Chrome-браузером на Windows. Агент использует LLM (OpenAI) для планирования и принятия решений, Playwright для управления браузером, и структурированную память для контекста.

## Особенности

- 🤖 Автономное управление видимым Chrome браузером
- 🧠 Использование LLM (OpenAI GPT-4o-mini/GPT-4o) для планирования и принятия решений
- 👁️ Vision-анализ скриншотов для точного определения координат элементов
- 🔒 Security layer с подтверждением опасных действий
- 📝 Структурированная память (EPHEMERAL, WORKING SUMMARY, FACTS)
- 🎯 Subagents: Planner, DOM-Analyst, Critic (через интерфейсы)
- 📸 Скриншоты на каждом шаге для vision-анализа
- 📊 Логирование и трассировка всех действий
- 🔄 REPL для интерактивного управления
- 🏗️ Модульная архитектура с чётким разделением ответственности

## Установка

1. Клонируйте репозиторий:
```bash
git clone <repository-url>
cd testTask
```

2. Установите зависимости:
```bash
go mod download
```

3. Установите Playwright browsers:
```bash
go run github.com/playwright-community/playwright-go/cmd/playwright@latest install chromium
```

4. Создайте файл `.env` на основе `configs/env.example`:
```bash
copy configs\env.example .env
```

5. Отредактируйте `.env` и укажите:
   - `OPENAI_API_KEY` - ваш OpenAI API ключ
   - `OPENAI_MODEL` - модель LLM (рекомендуется `gpt-4o-mini` для vision-анализа)
   - `CHROME_PROFILE_DIR` - путь к профилю Chrome (см. инструкцию ниже)
   
   Полный список параметров см. в `configs/env.example`

## Настройка Chrome Profile

**ВАЖНО**: Перед запуском нужно правильно настроить путь к профилю Chrome.

### Способ 1: Использовать существующий профиль Chrome (рекомендуется для Google аккаунтов)

1. Найдите путь к вашему профилю Chrome:
   - Откройте Chrome
   - Введите в адресной строке: `chrome://version/`
   - Найдите строку "Profile Path"
   - Обычно это: `C:\Users\<ВашеИмя>\AppData\Local\Google\Chrome\User Data\Default`
   - Если используете несколько профилей, может быть `Profile 1`, `Profile 2` и т.д.

2. Укажите этот путь в `.env`:
   ```
   CHROME_PROFILE_DIR=C:\Users\Daniil Koreshkov\AppData\Local\Google\Chrome\User Data\Default
   ```

3. **ВАЖНО**: 
   - Закройте Chrome перед запуском агента, иначе будет ошибка доступа к профилю
   - Убедитесь, что вы уже залогинены в нужные аккаунты (Google, Ozon, Yandex Market и т.д.) в этом профиле
   - Агент автоматически обходит детекцию автоматизации Google, используя специальные флаги Chrome

### Способ 2: Создать отдельный профиль для агента

1. Создайте новую директорию для профиля (например, `C:\ChromeAgentProfile`)

2. Укажите этот путь в `.env`:
   ```
   CHROME_PROFILE_DIR=C:\ChromeAgentProfile
   ```

3. При первом запуске Chrome создаст новый профиль в этой директории
4. Вам нужно будет вручную залогиниться в нужные сервисы при первом использовании

### Работа с Google аккаунтами

Агент автоматически обходит детекцию автоматизации Google с помощью:
- Флагов Chrome: `--disable-blink-features=AutomationControlled`, `--exclude-switches=enable-automation`
- JavaScript-скрипта, скрывающего `navigator.webdriver`

Это позволяет использовать уже авторизованный профиль Chrome без блокировок Google. Если вы видите ошибку "Не удалось войти в аккаунт", убедитесь, что:
1. Используете правильный путь к профилю (где вы уже залогинены)
2. Chrome полностью закрыт перед запуском агента
3. Профиль не заблокирован другим процессом

## Использование REPL

После запуска доступны следующие команды:

- `task <description>` - Запустить новую задачу (например: `task найти товар iPhone на Ozon и добавить в корзину`)
- `status` - Показать статус агента
- `pause` - Приостановить выполнение
- `resume` - Возобновить выполнение
- `approve` - Одобрить опасное действие
- `deny` - Отклонить опасное действие
- `mode <live|dryrun>` - Установить режим (live - реальное выполнение, dryrun - только логирование)
- `help` - Показать справку
- `quit` / `exit` - Выход

### Пример сессии:

## Логи и трассировка

Все логи сохраняются в `./runs/<timestamp>/`:

- `run.log` - JSON логи всех операций (zap logger)
- `trace.json` - Трассировка LLM вызовов и tool calls
- `screens/` - Скриншоты на каждом шаге (`step-XXX.png`, `step-XXX-result.png`)

### Анализ логов

**run.log** содержит структурированные JSON логи:
- Все действия агента (шаги, инструменты, результаты)
- Ошибки и предупреждения
- Progress check результаты
- Critic check результаты
- Обновления плана

**trace.json** содержит:
- Все запросы к LLM (prompts, responses)
- Tool calls и их результаты
- Vision-анализ запросы и ответы

**Скриншоты:**
- `step-XXX.png` - скриншот перед действием (для vision-анализа)
- `step-XXX-result.png` - скриншот после действия (для progress check)

### Просмотр логов

Для просмотра JSON логов можно использовать `jq`:
```bash
cat runs/20260122-020420/run.log | jq '.'
```

Или фильтровать по уровню:
```bash
cat runs/20260122-020420/run.log | jq 'select(.level == "error")'
```

## Безопасность

- Агент автоматически запрашивает подтверждение перед опасными действиями:
  - Оплата
  - Оформление заказа
  - Отправка форм
  - Удаление
  - Отклик на вакансию

- Используйте `mode dryrun` для тестирования без реальных действий.

### Как работает dry run

В режиме `dryrun`:
- ✅ LLM запросы выполняются (планирование, анализ, проверки)
- ✅ Скриншоты создаются
- ✅ Логи записываются
- ❌ Браузерные действия НЕ выполняются (click, type, navigate не изменяют страницу)
- ❌ Изменения на странице не происходят

Это позволяет безопасно проверить план и понять, что будет сделано, без риска реальных изменений.

## Архитектура

Подробное описание архитектуры см. в [docs/architecture.md](docs/architecture.md).

### Ключевые компоненты

- **Agent** - оркестратор, управляет выполнением плана, координация всех компонентов
- **Subagents** - Planner (планирование), Analyst (vision-анализ), Critic (критика плана)
- **VisionActionHandler** - обработка click/type через vision-анализ скриншотов
- **DOMValidation** - валидация координат через DOM-анализ перед кликом/вводом
- **Navigation** - разрешение URL для навигации
- **Browser** - Playwright adapter для управления Chrome
- **Memory** - структурированная память (Ephemeral, WorkingSummary, Facts)

### Как это работает

1. **Планирование**: Planner разбивает задачу на шаги
2. **Vision-анализ**: Для click/type действий делается скриншот, LLM анализирует изображение и определяет координаты элемента
3. **DOM-валидация**: Координаты проверяются через DOM-анализ для подтверждения корректности
4. **Выполнение**: Действие выполняется по координатам или через fallback на selector-based поиск
5. **Самопроверка**: Многоуровневая система проверки:
   - **Progress Check**: После каждого важного действия проверяется, достигнут ли ожидаемый результат
   - **Critic Check**: Периодическая проверка каждые N шагов для оценки общего прогресса
   - **Error Recovery**: При ошибках план автоматически обновляется для обхода проблемы
6. **Адаптация**: При обнаружении отклонений или проблем план автоматически обновляется через Planner

Подробнее об алгоритме самопроверки см. в [docs/architecture.md#алгоритм-самопроверки-и-адаптации-плана](docs/architecture.md#алгоритм-самопроверки-и-адаптации-плана)

## Troubleshooting

### Проблема: "target closed: Target page, context or browser has been closed"

**Решение**: Закройте все окна Chrome перед запуском агента. Агент использует persistent context и не может работать, если Chrome уже запущен.

### Проблема: Агент не находит элементы на странице

**Возможные причины и решения**:
1. Элемент находится вне видимой области - агент автоматически использует scroll, но может потребоваться несколько попыток
2. Элемент загружается динамически - увеличьте `BROWSER_ACTION_TIMEOUT` в `.env`
3. Элемент скрыт overlay - агент автоматически определяет overlays, но может потребоваться ручное вмешательство

### Проблема: Медленное выполнение задач

**Оптимизация**:
- Используйте `gpt-4o-mini` вместо `gpt-4o` для vision-анализа (быстрее и дешевле)
- Уменьшите `AGENT_CRITIC_INTERVAL` если задачи простые
- Уменьшите `BROWSER_ACTION_TIMEOUT` для ускорения при отсутствии элементов

### Проблема: Агент выполняет неправильные действия

**Решение**:
- Используйте `mode dryrun` для проверки плана перед реальным выполнением
- Проверьте логи в `./runs/<timestamp>/run.log` для понимания решений агента
- Используйте `pause` для остановки и анализа текущего состояния
- Проверьте скриншоты в `./runs/<timestamp>/screens/` для визуального анализа
- Проверьте `trace.json` для понимания промптов и ответов LLM

### Проблема: Агент застрял в цикле повторных попыток

**Решение**:
- Проверьте логи на наличие повторяющихся ошибок
- Используйте `pause` для остановки
- Проверьте, не заблокирован ли план (status покажет `blocked: true`)
- Если план заблокирован, проверьте `block_reason` в логах
- Попробуйте запустить задачу заново с более детальным описанием

### Проблема: Ошибки OpenAI API

**Возможные причины**:
- Неверный API ключ - проверьте `OPENAI_API_KEY` в `.env`
- Превышен лимит запросов - увеличьте `OPENAI_MAX_RETRIES` или подождите
- Таймаут запроса - увеличьте `OPENAI_TIMEOUT` (особенно для vision-анализа)

## Лучшие практики

### Формулировка задач

- **Будьте конкретны**: "найти товар iPhone 15 Pro на Ozon" лучше, чем "найти iPhone"
- **Указывайте сайт**: "на Yandex Market" помогает агенту сразу понять, куда идти
- **Разбивайте сложные задачи**: Лучше несколько простых задач, чем одна сложная
- **Используйте контекст**: "добавить в корзину и открыть корзину" даёт больше контекста

### Оптимизация производительности

- Используйте `gpt-4o-mini` для большинства задач (быстрее и дешевле)
- Настройте `AGENT_CRITIC_INTERVAL` в зависимости от сложности задач:
  - Простые задачи: увеличьте до 10
  - Сложные задачи: уменьшите до 3
- Используйте `BROWSER_ACTION_TIMEOUT` для баланса скорости и надёжности:
  - Быстрые сайты: 30s
  - Медленные сайты: 90s

### Отладка

1. **Используйте dry run** для проверки плана:
   ```
   agent> mode dryrun
   agent> task ваша задача
   ```

2. **Проверяйте логи** после выполнения:
   - `run.log` - общие логи
   - `trace.json` - LLM запросы
   - Скриншоты в `screens/`

3. **Используйте pause/resume** для анализа:
   ```
   agent> task ваша задача
   agent> pause
   agent> status
   agent> resume
   ```

4. **Анализируйте скриншоты** для понимания, что видит агент

### Работа с ошибками

- Если агент застрял, используйте `pause` и проверьте логи
- Если план заблокирован, проверьте `block_reason` в логах
- Если элемент не найден, проверьте скриншоты - возможно элемент вне видимой области
- Если прогресс не соответствует ожиданиям, агент автоматически обновит план
